# Codex 连续交互协议

这是 StudyMate 总控的交互协议。开始学习流程、恢复会话或首次弹出选择前读取；子角色不执行本协议。学习规则仍由各教学技能负责。普通答疑只恢复相关节点，不强迫用户先完成建课表单。

## 选择工具与窗口

以本次工具列表、参数 schema 和模式限制为准，不能因文档列了名字就调用不存在的工具，也不切换到 Plan 模式仅为了弹窗。

| 当前可用能力 | 总控行为 |
| --- | --- |
| `request_user_input_async` 或等价异步提问工具 | 适用于目标、偏好、课程/项目选择等工具允许的问题；发出后返回的 accepted 只表示卡片已送达，不是用户回答。 |
| `request_user_input` 或等价同步提问工具 | 仅在当前模式允许且问题满足工具用途时调用；工具返回真实答案后再继续。若只允许可选澄清，不用它收集必须的学习决策。 |
| 没有合适的提问工具 | 用普通对话提出同一个问题，给 2-3 个简短选项或请用户自由回答；等待下一条用户消息，收到后接续。 |

每次只发一个需要学生决策的问题，通常给 2-3 个选项且不超过实际工具上限；用户一次说出多个答案时全部吸收。工具支持多题不等于要把卡片填满。偏好选择的推荐项放第一且标“推荐”，选项互斥并能说清差异；工具自带自由输入时不另加“其他”。用户自由输入有效，不强迫映射到选项。

**教学题目使用课件或普通对话作答**；不把测验包装成带推荐答案的偏好弹窗。需要代码、文件或截图时使用宿主支持的附件通道或普通对话，不用只能接收文本的选择工具收附件。平台权限确认用宿主原生审批机制，不由课程选项代替。

异步工具的典型参数形状（仅当实际 schema 一致）：

```json
{
  "questions": [{
    "title": "这门 Python 课你想做哪个项目？",
    "options": ["整理文件的小工具（推荐）", "分析一份表格数据", "做一个小网页"]
  }]
}
```

同步工具若要求 header/id/options，则按它的 schema 分别填写 label 与 description，不复用异步 JSON。单选工具不强行表示多选、评分或上传文件。

## 发问 → 等待 → 消费 → 继续

1. **准备**：从消息和磁盘恢复已有答案。只有答案会影响后续且确实缺失才发问，避免“问完目标又问想学什么”。先保存 pending（题目唯一 id、科目相关 topic、问题、选项、回答后阶段）。一次只保留一个待处理问题。
2. **送出**：调用可用提问工具一次。记录本轮工具返回的关联信息；在同一会话把 questionItemId 等回传标识和 pending.id 对应起来，不把工具内部 id 当成用户答案。工具明确失败时只改用一次普通提问，不循环调用。
3. **等待**：只做与该答案无关的准备，如读取已有资料、检查运行环境。不要提前决定项目、生成依赖该选择的课程或为学生选择默认项；预选、高亮、accepted、空返回、超时和用户沉默都不是回答。
4. **保持会话**：若宿主支持等待/让出执行，使用其机制等待异步消息，长等待分段保持响应；不要靠重复发卡片刷新。没有等待机制或宿主交还控制时，保留 pending，只用一句话说明待答问题，不宣告工作完成、不再创建“下一步”弹窗。卡片接续依靠宿主回传，插件不能自行模拟点击或保证窗口一直打开。
5. **接收**：下一条输入先判断它是答案、补充、纠正、旁问、暂停还是换科目。文本直接回答与工具回传同等有效；提取用户一次给出的多项信息。只关联当前问题/科目；能识别的旧 questionItemId、已消费 id 或旧科目回传忽略，不重复写记录；无法判断“第二个/可以”等短答属于哪一题时只澄清指代。
6. **消费**：将实际回复写为 JSON 值，调用下方 `answer` 命令；它核对 pending.id 后保存到 answers（含 topic 与原文/选项意义），清除对应 pending 并继续到 resume_phase。总控接着用 `update` 保存具体 next_action 或下一道必要问题。过期/重复 id 失败时先重读，不换成当前 id 重试旧答案。答案足够便自动接到下一步，不要求用户再说一次“继续”。用户改主意时，以最新明确选择为准，用 `update` 清除失效的下游假设与待问项；已完成课程和学生作品保留。

可选问题明确跳过后使用已说明的合理假设。若同步工具文档要求空返回继续最佳判断，仅对可选偏好这样做，并标明是假设；它不是已回答，也不写成用户同意。必要缺项通过普通对话继续获取。不要用超时替代学习目的、答题证据或任何授权。

## 课程阶段与停止点

| 阶段 | 自动完成的工作 | 等学生的边界 |
| --- | --- | --- |
| clarify | 吸收已有背景，仅补关键缺项 | 目标、基础或项目等必要选择 |
| plan | 资料、大纲、校验、建科目、更新主页 | 用户仅要大纲时交付；要“开始学/直接第一课”则进入 produce |
| produce | 按节点 kind 依次讲解、出题、搬运、渲染、检查、预览 | 材料交付后进入 learn/practice，等真实阅读或作答 |
| learn / practice | 就地答疑，指向具体页面/题目/任务路径 | 学生的理解、答案、执行证据或下一步选择 |
| review | 由评估角色判断证据，总控记录结论 | 有新路线选择才弹窗；明确“继续”时直接进入相应节点 |
| paused | 完成保存并指出下次恢复点 | 用户再次要求继续；不追发选择题 |

“继续”必须联系当前阶段：盘问中继续补缺项；备课中接未完成步骤；课件已生成则回到该课的学习位置；作业中继续作业，不能跳成下一课。“我学完了/下一课”可以进入原教学规则的进度与评估分支，但不凭这句话认定掌握。

有明确续学科目或仅一个有效活跃科目时直接恢复，不展示所有科目让用户重选。多个科目且意图不明才展示简短选择。用户换科目后保存旧科目断点与摘要，再切换当前路径；旧弹窗、角色返回、旧节点的“完成”不能推进新科目。

一轮只准备当前授权节点或用户明确要求的范围，不自动做完课程。没有“最多两课后强制结束”的限制，学生需要继续就继续；不要为了防止对话过长主动替学生结束。

## 持久化与恢复

总控用 `<root>/scripts/interaction_state.py` 管理工作区内 `.learning/interaction.json`。它只存流程断点，不代替已有 MEMORY、progress、assessments 或 sessions，也不保存凭据。脚本不用 PyYAML；工作区必须是显式绝对路径，且已有 `.learning/`，不能是插件缓存或插件源目录。

```text
<python> -X utf8 '<root>/scripts/interaction_state.py' --workspace '<LEARN_WORKSPACE>' read
<python> -X utf8 '<root>/scripts/interaction_state.py' --workspace '<LEARN_WORKSPACE>' update --input '<STUDYMATE_SCRATCH>/interaction-next.json' --expected-revision 0
<python> -X utf8 '<root>/scripts/interaction_state.py' --workspace '<LEARN_WORKSPACE>' answer --question-id 'python-project-1' --input '<STUDYMATE_SCRATCH>/reply.json' --expected-revision 1
```

先用文件工具把 JSON 写入暂存文件再传路径，不把学生原文拼入 shell。`reply.json` 是实际回答的 JSON 值，例如 `"我选表格数据分析"`；不能写工具的 accepted 回执。`read` 的 revision 为并发校验依据；示例的 0 和 1 仅表示首次创建与随后的回答，实际调用必须使用刚读到的值。

**`update` 是完整替换，不是局部补丁。** 从最新 `read` / `answer` 成功返回的状态移除 `schema_version` 和 `revision`，保留七个业务字段及已有 answers，再修改需要的字段。不要在消费回答后复用发问前的旧 JSON，否则会抹掉刚保存的答案。清理失效假设时只改受影响项，不丢弃其他科目的有效信息。示例如下（元数据由脚本生成）：

```json
{
  "active_subject": null,
  "phase": "clarify",
  "node_id": null,
  "intent": "学 Python，能独立做一个小工具",
  "answers": {
    "python-goal-1": {"topic": "python.goal", "value": "做一个小工具"}
  },
  "pending": {
    "id": "python-project-1",
    "kind": "preference",
    "topic": "python.project",
    "question": "你想做哪个项目？",
    "options": [
      {"id": "files", "label": "整理文件的小工具"},
      {"id": "table", "label": "分析一份表格数据"},
      {"id": "web", "label": "做一个小网页"}
    ],
    "resume_phase": "clarify"
  },
  "next_action": "收到项目选择后，补齐尚未说明的基础与时间"
}
```

`active_subject` 是 `.learning/subjects/` 下的科目 slug，未建科目前可为 null。`node_id` 对应当前大纲节点；一次回复里的额外信息在 answers 分别保存，后续只问缺项。`pending.kind=learning_check` 仅表示等待教学作答，不自动生成提问工具调用或评分。暂停时 phase=paused、pending=null，next_action 写清恢复位置；已回答信息保留。

恢复顺序：本次明确指令 → 当前会话尚未处理的回复 → 交互断点与最近会话摘要 → progress 和实际文件。断点中的科目/节点必须与档案核对，文件被移动或删除时说明具体缺项，不静默建一门同名课。已验证的内容、题库或 HTML 存在就接着后续步骤，不重复产出；只有草稿存在不能当作已通过检查。重开后没有可用的原角色进程，就带着路径与失败/未完成证据重新执行那个角色，不能沿用旧 agent id。

每次阶段完成或用户回答后保存，而非等会话结束。修订冲突重读、损坏保留原文件并报具体问题；保存失败时说明本轮不能保证自动恢复，并给出可复制的简短续学信息。状态文件不负责多个会话的课程文件锁；同一科目依然只允许一个写入者，不在后台覆盖另一任务的进度。

## 角色返回与界面呈现

派工给绝对路径、科目、节点、已选项目/载体、具体产物与本次任务边界。仅并行没有相互依赖、不会写同一文件的任务；等待期间总控仍接学生消息，不另开用户可见任务。子角色交付后，总控核验当前意图与节点仍相符才采用；暂停或改目标后到达的草稿先留在暂存处，不自行发布成新课。

用户暂停、换科目或改变已派工目标时，先用宿主实际提供的中断/消息工具让受影响角色停止旧任务，再核对已写入的文件并保存断点。不能终止的调用如实记录为仍待处理，暂不派会写同一文件的新任务。角色可能已直接写入课件源文件，因此不能只丢掉返回消息就声称旧任务没有留下改动。

对学生说“正在准备课件/核对练习”，不暴露内部角色调度、revision 或 JSON 字段。生成完成给页面绝对路径链接；有 Codex 文件/浏览器面板工具时展示已验证页面。一次最多一个当前行动：例如“打开本课，做完第一组自测后把答案发给我”。不会把结束一条子任务、调用提问工具或成功写文件当成完成用户的学习目标。
