# 七个可交叉的学习入口

按需用于区分候选与解释路径，不把全部卡片一次展示给学生。入口可组合；语言、框架和行业只是目标的线索。成果均是候选，未确认之前不生成题目、lab 或课程。

| 入口 | 初步区分 | 可做出的成果与阶段概览 | 先修与约束 |
|---|---|---|---|
| 应用开发与自动化 | Web 应用、个人工具、重复工作自动化、AI 应用；使用模型做产品与研究模型原理不同，后者比较“机器学习与 AI 原理” | 可筛选资料的页面、文件整理脚本或笔记问答工具；基本编程 → 输入输出与交互 → 小工具及检查 | 按目标补编程与接口基础；AI 服务访问与费用待核实，可先用模拟响应搭流程 |
| 数据分析与数据工程 | 用数据回答问题，或采集、清洗、存储与维护数据流程 | 能解释局限的图表分析，或可重复运行的清洗流程；表格／编程与 SQL → 质量检查 → 分析结论或数据管线 | 按目标补统计、编程或数据库；从小数据开始，不默认云平台和集群 |
| 机器学习与 AI 原理 | 理解训练、评估与模型机制；区分基础理解、实验比较与研究目标 | 比较简单基线与小模型并解释误差；数据与编程 → 按需数学 → 训练、验证与误差分析 | 先修深度随目标调整，按任务补线性代数、概率或微积分；不默认专用 GPU，更不承诺普通设备能训练大模型 |
| 系统、可靠性与性能 | 操作系统、网络、底层机制，或故障分析、可靠运行与性能优化 | 用日志定位故障，或测量程序优化前后的表现；编程与调试 → 进程／内存／网络 → 小系统观察与改进 | 按任务补命令行、并发等；特定 GPU 或分布式任务先确认环境 |
| 图形与游戏开发 | 图形渲染，或游戏交互和玩法实现 | 自己生成的简单场景图，或有操作与规则的微型游戏；编程 → 向量坐标与光照，或输入状态与交互 → 小原型 | 按分流补数学或编程；结合设备选小场景，不要求引擎与渲染器两条同时学 |
| 嵌入式、机器人与控制 | 设备、传感器与控制逻辑；分清硬件入门、仿真和反馈控制目标 | 条件允许时做传感控制小装置，或在仿真里解释输入、状态与输出；基础 → 输入输出／反馈 → 小任务 | **先询明设备条件，再提出具体路径**；设备问题另轮单问且计数。未知时只保留条件候选，不指定购买或硬件；无硬件可考虑仿真，说明它不覆盖真实接线、噪声和时序 |
| 数学探索与基础 | 独立数学兴趣，或补足其他方向所需数学 | 用图解释线性变换，或推导一个感兴趣的概率现象；具体问题 → 所需概念与推导 → 解释或回到原任务 | 按主题补代数、函数等，不要求先学全套数学，不以编程或求职作为唯一成果 |

同一目标可连接多个入口，例如笔记问答连接应用与数据；推荐时选主要起点，说明其他入口如何辅助。没有经历通常意味着从基础起步，不意味着不适合。没有兴趣线索时可给不同活动的宽候选并标暂定，不能据此宣称天赋或就业适配。
