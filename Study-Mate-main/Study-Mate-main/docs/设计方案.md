# StudyMate：辅助学生自学的 Agent 设计方案

> 版本：v1.4（2026-09-24）
> 定位：基于 DSH 的长期自学助手。先验证教学方法，再升级可视化主页。
> 阅读对象：产品经理、使用者。技术实现细节见 `docs/工程约束.md`。

---

## 1. 背景：要解决的五个问题

长期自学系统常见的五个毛病，以及本方案对应的解法：

| # | 常见毛病 | 本方案解法 |
|---|---------|-----------|
| 1 | 教学大纲模糊，学得浅 | 结构化课程路线图：每个知识点有目标、前置、资料、实践、误区、证据，可动态调整 |
| 2 | 不讲人话，听不懂 | 人话教学原则：先讲"解决什么问题"，用生活例子打底；"没听懂"就换讲法 |
| 3 | 路线长，单会话上下文吃不下 | 学习状态全部存成文件，会话只带"当前学到哪"，不背全部历史 |
| 4 | 出题简单、教条、脱离实际 | 四层练习：理解 → 改造 → 排错 → 应用（真实项目），以"能独立完成真实项目"为完成标准 |
| 5 | 课件提问污染主会话 | 局部提问由主教练亲自答，答完只写盘一条结构化学习记录、上下文只留一行摘要，不打断学习 |

## 2. 目标与边界（首版范围）

**做：**
- **长期陪伴式自学**：同时维护多门科目，每门科目独立管理、互不干扰
- **共享记忆**：跨科目、跨会话记住学习者的现有技能、水平、教学方式偏好
- **主页体系**：项目根一个课程总览页，每门科目一个主页（大纲路线图（点节点展开课件子卡片）+ 附件区）
- **新课程先聊清楚**：开新课前先问清"想学到什么程度""做什么项目配合""动手实操用什么方式"，再建课程
- **学习材料两件套**：每个知识点一份 HTML 课件（浏览器打开自学，内嵌练习即时反馈）+ 一份引导式实操（分步带你做、任务留给你亲手写、做完能立刻验证；载体由主教练在盘问时跟你确认——notebook / 源码+测试 / 页面 / 练习页）；讲解不占聊天
- **任意目录可开会话**：会话可以在任何工作区启动（选"学习模式"预设即可），学习数据集中存放在**学习工作区**，与会话所在目录无关
- **首版学科**：编程与软件工程（模型可扩展到其他学科）
- **内容来源分级**：稳定基础知识（概念、算法、语法、原理）直接用模型已有知识，不强制找资料；易变内容（框架 API、工具配置、版本差异）必须核对官方文档；冷门/新领域必须找来源
- **可迁移**：学习工作区整体复制到另一台机器，重新安装并指定工作区即可续学

**不做（YAGNI）：**
- 多用户账号、社交功能、积分排行榜
- 在线代码编辑器（用本地文件和终端）
- 自动生成全部课程内容（首版以模型知识 + 按需核对权威资料为主）
- 同时支持所有学科

## 3. 产品功能设计

### 3.1 多科目 + 共享记忆

系统长期跟踪同一个学习者，学习状态分两层：

**共享记忆**（跨科目、跨会话）
- 我是谁：现有技能、各领域当前水平
- 教学偏好：什么讲法有效、什么让人烦躁、例子偏好
- 学习习惯：可投入时间、节奏、常见卡点（如"概念懂了但写不出来"）
- 跨科目观察：反复出现的思维模式、需要长期留意的弱点

**科目文件夹**（每门科目一个）
每门科目装自己的大纲、进度、误解记录、会话摘要、课件、主页。科目之间零耦合：学 TypeScript 和学线代互不读取对方文件，只共享上面那份记忆。

**科目元数据怎么维护**：每门科目有四份"元数据"文件——科目信息（名称/目标/状态）、使命（为什么学、成功标准、不学什么）、资源清单（延伸阅读 + 易变内容的核对来源）、术语表（这门课的规范用词）。它们**低频更新、由主教练直接维护**——主教练全程在场，判断最准（比如"学生是不是真会用这个术语了"它亲眼见过），为这种小改动派个角色再转一圈不划算。

| 文件 | 什么时候改 | 规则 |
|---|---|---|
| 科目信息 | 开课/暂停/完成、目标变化 | 目标变化先跟你确认 |
| 使命 | 你的目标、配合项目或约束变了 | **必须你确认**；旧使命留痕，不悄悄替换 |
| 资源清单 | 新资料被课件采用、旧资源失效或质量不够 | **定位：延伸阅读 + 易变内容的核对来源**：只收高可信来源、每条写用途；失效的删掉不堆积 |
| 术语表 | 你**真的能用对**某个术语时（不是刚被介绍过） | 定义一两句；标出要避免的别名；课件用词以此为准 |

三份 Markdown（使命/资源/术语表）没有固定字段要求，**你也可以直接手改**——它们就是给人读的，改完下次会话生效。

**资料什么时候才需要找**（模型已经知道大部分知识，找资料只解决三件事）：核对易变细节（API 签名、版本差异、废弃方法）、给一手来源供你深挖、补模型盲区（冷门库/新框架）。对应分级：

| 知识点类型 | 资料要求 |
|---|---|
| 稳定基础知识（概念、算法、语法、原理） | **不强制找**；节点 `resources` 可空或只放一条延伸阅读，课件标注"通用基础知识" |
| 易变/版本相关（框架 API、工具配置、部署） | **必须核对官方文档**再写课件 |
| 冷门/新领域 | **必须找**；找不到可靠来源就在资源清单的缺口小节记一笔，提醒课件格外小心 |

**档案记录也由主教练自己写**（进度、误解、会话摘要、学习记录、共享记忆、主页刷新）：这些内容的信息源就在主教练的上下文里——它亲历了整场会话。派角色去写，主教练得先把信息转述进派发指令（等于先草拟一遍），角色再加工成文件，多一道转述、还更慢。规则保留成一份"档案维护规范"，主教练照着读写即可。

**什么才派角色**：需要**外部检索、大量生成或独立验证**的工作——拟大纲（要查权威资料、设计依赖图）、做课件（要写 HTML、复用组件）、出题评估（要跑代码验证）。这些工作过程不进主教练上下文，只回结果，派出去才真的省。

**新课程先聊清楚（盘问）**
用户提出学新科目时，先问清楚再建课程，一轮轮问、问完再展开下一轮，直到没有遗漏。**盘问由主教练（总控）亲自进行**——只有它能与用户直接对话，子 agent 没有用户交互通道，只能经总控中转：
- **必问**：①想学到什么程度（了解 / 能上手 / 能独立做项目 / 精通）；②学习过程中想做什么项目来配合（给你 3 个以上候选挑一个）；③动手实操用什么方式（结合你的技术栈给候选：notebook / 源码+测试 / 页面 / 练习页…）
- **追问**：时间投入、已有基础、讲法偏好、明确不学什么
- **已经记录过的信息不问第二遍**

**首次使用**：只问三件事——想学什么、当前基础、教学偏好。之后每次会话开场自动恢复进度，不重复询问。

### 3.2 可视化课程大纲（路线图）

课程不是章节列表，是**知识点组成的路线图**，节点之间是前置依赖关系：

```text
HTTP 基础
   ↓
Web 服务
   ├── 路由
   ├── 参数校验
   └── 错误处理
          ↓
数据库访问
          ↓
认证授权
          ↓
完整项目（毕业任务）
```

每个知识点包含：要解决的问题、前置知识、核心概念、推荐资料（**可空**——稳定基础知识不必凑资料）、最小实践、常见误区、现实应用、检验任务、完成证据、掌握度。

节点状态：`未开始 / 学习中 / 初步理解 / 能独立应用 / 需要复习 / 已通过项目验证`。

**路线动态调整的依据**：测验结果、代码运行结果、反复提问的位置、项目暴露的错误、实际投入时间。调整时保证：已学内容不悄悄删除、历史版本可查。

### 3.3 人话教学：原则性指引

> 讲法原则见**课件设计规范**的「讲法倾向」一节（它与课件的要素、实操规范、记忆设计一起，是课件的唯一约束来源）；**反馈处理不属课件规范**——学生反馈只到主教练，由主教练现场应对（见 §3.6）。

讲解风格写成**倾向性指引**，给方向、不卡步骤，让系统按现场判断取舍。两个原则：

1. **正面表述**：写"先建立问题感"，不写"禁止先给定义"——否定式规则反而把被禁止的行为拽进注意力中心。
2. **可被覆盖**：这些是默认倾向，学生的明确要求、科目性质、`共享记忆` 里的个人偏好都可以覆盖它们。

指引围绕几个好记的词展开：

| 词 | 含义 |
|---|---|
| 问题感 | 先让学生感到"这是个什么麻烦"，概念才有落点 |
| 具体先行 | 例子在前，定义在后 |
| 小步 | 一次少给；宁可分两次讲完 |
| 学生的语言 | 术语首次出现顺带一句大白话；沿用学生自己的说法 |
| 参与 | 留出预测、改一行、复述的空间，暴露理解断点 |
| 连回项目 | 知识与他在做的事有连接时才不容易忘 |

**反馈处理（主教练现场亲自做，学生反馈只到主教练，不进课件规范）**："没听懂"→换更近的例子或降一层抽象；"太简单"→加边界、取舍、反例；要答案→先给线索、按需加码；"有什么用"→先答用途再回内容。

### 3.4 四层练习与真实项目

每个知识点配四层任务，评价的不是"答对"，而是"能否解释原因、处理边界、读懂报错、写测试、迁移应用、说明取舍"：

| 层 | 类型 | 示例 |
|---|------|------|
| L1 理解 | 判断/解释/预测输出 | "这个循环输出什么？为什么？" |
| L2 改造 | 修改已有代码观察变化 | "把查询改成流式处理，看行为差异" |
| L3 排错 | 真实 bug 定位 | 给一个含 bug 的接口，定位原因 |
| L4 应用 | 放进自己的项目 | 提交代码 + 测试结果 + 解释 |

### 3.5 学习材料：HTML 课件 + 引导式实操

**每个知识点产出两件套**：一份自包含的 HTML 课件（讲解 + 检索练习）+ 一份引导式实操（动手材料，载体由主教练在盘问时跟你确认）。学生用浏览器读课件，按确认的载体做实操。讲解不发生在聊天里，发生在材料里。

**为什么用文件而不是聊天**：
- **不占聊天**：材料是文件，读时的局部提问由主教练简短回答、写盘摘要，主会话不堆积长问答——直接解决"上下文吃不下"和"提问污染"
- **即时反馈**：课件内嵌选择题答完立刻判对错；实操跑一下就能看见结果
- **可回看**：课件与实操按编号归档，随时回看，不像聊天记录会滚动消失

**每份课件的要素**（必须做到，写在课件设计规范里）：
1. **真实场景开场**——从熟悉的真实问题切入，不先抛定义
2. **术语先来历后定义**——先讲它解决什么问题、为什么需要、历史来历，再给定义
3. **权威教材的深度**——讲透前提、推导、边界；不做速成课，内容长没关系
4. **引导式实操**——见下

> 配套项目不属课件约束：由主教练在开课盘问时给你 3 个以上候选项目挑选（§3.1），选定后课件负责在每课里给它逐课埋线。

**记忆设计**（借用成熟的学习科学，唯一的"难度/间隔/交错"出处）：区分"流畅度"（当场能复述 ≠ 学会了）与"存储强度"（过段时间还记得住，才是目标）；用**合意困难**设计练习——检索练习（回忆而非重读）、间隔（分散到多次会话）、交错（技能练习混合相关主题）；难度落点始终在**最近发展区**（既不是纯复习也不是一步跨太远，用学习记录校准）。

**实操怎么做（引导式）**：载体由主教练在盘问时跟你确认（结合科目性质与你的技术栈，记进 `lab/README.md`），载体定下后按对应形态组织。内核是五条——分步引导、任务留白（亲手做）、可验证、即时反馈、卡壳先引导不给答案；成品只放 `solutions/` 供做完对照。常见载体的形态：

| 载体 | 形态 | 怎么验证 |
|---|---|---|
| Jupyter notebook | `NN-主题.ipynb` | 教程格预执行带输出 + `assert` 自检 |
| 源码 + 测试 | `NN-主题/`：源码 + 测试文件（JS/TS/Go/Rust…） | 跑测试（jest / go test / cargo test…） |
| 页面 | HTML + JS 页面（前端/可视化） | 眼见效果 + console 断言 |
| SQL | `.sql` 文件 + 期望结果 | 结果集对照 |
| 命令行 | 脚本 + 沙箱 | 期望输出 diff |
| 练习页 | Markdown/HTML + 数值验算脚本（数学/理论） | 步骤对照 + 数值验证 |
| 清单 | 检查清单 + 自评记录（非技术/技能） | 清单勾选 / 录音复述 |

**贯穿三条线索**：每课回扣最终目标（"这段在整体里处于什么位置"）；配套项目从早期就作为实操素材逐课埋线（不等到最后才做）；编程类科目亲手实现与现成库结果对照。

**配套内容**：每门科目还有速查文档（cheat sheet、术语表）、学习记录（记"真的学会了什么"，决定下次教什么）、资源清单（延伸阅读 + 易变内容的核对来源）。

### 3.6 局部提问（读课件时随时问）

学生在任何时候都可以提问：把看不懂的一段文本/代码/报错原样贴回会话，说一句哪里不懂即可（不需要特殊格式）。**由主教练亲自回答**，回答控制在一小段内，答完立即把一条结构化学习记录写入该科目的误解记录，**不打断当前学习**，处理完回到刚才的地方继续。主教练上下文里只留一行摘要（topic、importance），详细问答本身短小、加上 DSH 的上下文压缩与会话摘要，污染可控。

### 3.7 主页体系（课程总览 + 科目主页）

**根主页**（课程总览）：
- 列出所有科目：名称、状态、上次学习日期、当前节点、掌握度
- 从这进入任意科目的主页；每次学习从这里开始

**科目主页**：
- **大纲路线图**：按依赖分层渲染知识点，节点按状态着色（未开始灰 / 学习中蓝 / 能独立应用绿 / 需要复习黄 / 已通过项目验证深绿）；**点卡片原地展开该知识点的课件子卡片**（父卡片不移动，子卡片用竖线挂在父节点下），点子卡片打开课件
- **附件区**：参考文档（HTML 速查页）、术语表、资源清单、学习记录、会话摘要，一列排开、可惯性滚动
- 顶部：科目状态徽标、使命一句话、项目里程碑；大纲区块右侧是各状态计数

**主页自动更新**：新建科目、节点状态变化、新增课件时，主页自动重新生成，不用手改。

**模板与生成器的分工**（影响你设计页面时怎么写）：
- **模板**（引擎项目 `templates/home-index.html`、`subject-index.html`）= 页面的**骨架与样式**：你在这里做视觉设计（框架、CSS、布局），数据位置留**占位符**（HTML 注释，如 `<!-- @LEARN:SUBJECT_CARDS -->`）
- **生成器**（`scripts/gen_home.py`）= 数据注入器：读模板 → 把占位符替换成真实数据（科目卡片、路线图、课件列表、页头标题）→ 输出到学习工作区
- **模板里不放示例数据**：示例数据放在 `examples/`，想预览页面效果就"模板 + 示例数据"跑一次生成器，看输出文件
- **改样式只改模板**：改完重跑生成器即可，生成器不碰你的样式代码

**占位符粒度：区块级 + 字段级混合**（判断标准：数量会变的用区块级，固定单值的用字段级）：

| 粒度 | 占位符 | 替换成 | 说明 |
|---|---|---|---|
| 区块级 | `<!-- @LEARN:SUBJECT_CARDS -->` | 全部科目卡片 | 数量不定 + 循环，模板无法预写，必须整块生成 |
| 区块级 | `<!-- @LEARN:ROADMAP -->` | 大纲路线图 | 节点数量不定 + 依赖排序 + 状态着色 |
| 区块级 | `<!-- @LEARN:PROJECT -->` | 项目里程碑 | 结构固定但内容不定，整块生成 |
| 区块级 | `<!-- @LEARN:ATTACHMENTS -->` | 附件分组 | 数量不定 + 分组 + 循环 |
| 字段级 | `<!-- @LEARN:TITLE -->` | 科目名 | 固定单值，页头排版由你定 |
| 字段级 | `<!-- @LEARN:STATUS -->` | 科目状态徽标 | 固定单值 |
| 字段级 | `<!-- @LEARN:MISSION -->` | 使命一句话 | 固定单值 |

**区块的样式接口（class 约定）**：生成器渲染的区块带稳定 `learn-` 前缀 class（如 `learn-subject-card`、`learn-node`、`learn-node--done`）。你写 CSS 打这些 class 即可定制外观，不需要碰占位符或生成器；节点状态着色用 class（`learn-node--done` / `--learning` / `--review` 等）而不是内联颜色。

### 3.8 学习档案与复习机制

每次会话结束生成一页摘要（学了什么、下一步、薄弱点）。复习依据来自两处：该科目的误解记录（知识性误解）和共享记忆里的思维模式观察（跨科目倾向）。

### 3.9 三个区域：项目、安装、学习工作区

**会话不是在项目目录里跑的**——用户可能在任何目录（写代码的项目、临时工作区）启动会话。所以系统明确分成三个区域，互不混用：

| 区域 | 位置 | 放什么 | 谁碰它 |
|------|------|--------|--------|
| **引擎项目** | 源码仓库 | 系统源码：skill、模板、预设源、脚本、示例、文档 | 开发者维护；普通安装无需克隆 |
| **用户级安装** | `~/.dsh/` | `studymate/engine/`（引擎副本）、学习模式预设、`studymate-config.yaml`（学习工作区定位） | `npx` 安装器写入 |
| **学习工作区** | 首次安装默认 `~/StudyMate/`，已有配置会沿用 | **你的学习数据**：`.learning/`（共享记忆 + 全部科目）、根主页、科目主页 | 总控读写；独立备份和迁移 |

**为什么这样分**：
- **学习模式预设**装在用户级（`~/.dsh/`），预设里记着已安装引擎的技能目录并锁定了范围，所以你在任何目录选"学习模式"开会话都能用、且只加载 StudyMate 自己的技能——这是"任意目录可开会话"的前提；别的会话也看不到 StudyMate 的技能
- 学习数据集中在学习工作区，由一份配置文件定位，总控开场读它就知道去哪读写——会话目录里不会散落学习文件
- 换机器 = 复制学习工作区（包括隐藏的 `.learning/`）+ 重新安装并指定该目录

**定位机制**：`npx` 安装器把学习工作区路径写进 `~/.dsh/studymate-config.yaml`。总控每次开场先读这份配置，再开始读学习状态。换目录时先复制学习数据，再通过 `--workspace <目录>` 指定新位置。Codex 导入完整插件后，在对话中指定独立的学习工作区，详见 [安装说明](安装.md)。

## 4. 一次学习会话是怎样的

**开场**
1. 打开会话，系统读取共享记忆，列出已有科目，打开课程总览页
2. 你选一门继续，或报一个新科目名

**开新课**
3. 系统先盘问（§3.1）：想学到什么程度？**给你 3 个以上候选项目**让你挑一个来配合——问清楚才建课程
4. 生成大纲路线图 + 科目主页，开课

**学一个知识点**
5. 系统产出该知识点的**两件套**：课件（浏览器打开）+ 引导实操（按载体打开：notebook / 编辑器+测试 / 练习页）
6. 你读课件、做里面的检索练习（答案即时反馈）；然后做实操——引导部分带你看（并给结果）、**▸ 你的任务** 留给你亲手写，做完当场验证（断言 / 测试 / 对照）
7. 读不懂的随时圈起来问（§3.6），问完接着学
8. 学完汇报，系统出题评估（§3.4），你的项目交付物会跑真实验证
9. 通过 → 更新进度、记录"真的学会了"；没通过 → 补练或换讲法

**结束**
10. 生成会话摘要、更新共享记忆、刷新主页

## 5. 实现方式概览

- **一个"学习模式"会话**：系统内部有五个分工角色——资料收集、采图、课程设计、讲解、练习评估——由主教练统一调度。你只跟主教练对话，看不到内部协作；**所有需要你回答的环节（盘问、确认、局部提问）以及全部档案记录都由主教练亲自做**，角色只跟主教练交接
- **任意目录可开会话**：能力装在用户级（`~/.dsh/`），学习数据由配置文件定位（§3.9），会话跑在哪都不影响
- **讲解在课件文件里，不在聊天里**：这是"上下文吃不下"问题的根本解法
- **状态全部是文件**：大纲、进度、记忆、课件都在学习工作区里，可迁移、可备份、可人工查看
- **主页是生成的**：从状态文件自动渲染，保证永远是最新的
- **可迁移**：学习工作区拷走 + 重新安装并指定该目录 = 换机器续学

## 8. 技能范围

学习会话只用 StudyMate 自己的一套 skill（引擎项目 `.dsh/skills/` 下 12 份，"学习模式"预设把它们指给会话）：

- **总控**：`learning-system`——开场、盘问、学习循环、档案维护的调度中枢
- **五个角色**：资料收集、采图、课程设计、讲解、练习评估（总控派出去干活，学生看不到）
- **六个协议**：可选方向探索、课件设计规范、四层练习、证据核验、答疑、档案维护（总控与角色按需加载；探索由总控亲自执行，见 [learning-discovery](../.dsh/skills/learning-discovery/SKILL.md)）

角色代称与派工时给的值见 [`文件归属.md`](文件归属.md)。

**"学习模式"预设把技能范围锁在 StudyMate 自己的目录**，不读 `~/.dsh/skills/` 里你已装的其他技能。两边互不干扰：学习会话里不会冒出写代码用的技能，你的其他会话里也不会冒出 StudyMate 的技能。

需要核实易变内容或找一手来源时，总控直接用联网检索工具查；要读大量资料就派子 agent 去查，结果由总控写盘。

## 9. 实施阶段划分

### 阶段一：核心闭环（先做，验证教学方法）

1. 项目脚手架 + 数据模板（含共享记忆、科目模板、课件组件）
2. 五个分工角色（资料收集、采图、课程设计、讲解、练习评估）+ 教学规范与协议（课件设计规范、四层练习、证据核验、答疑、档案维护）
3. 总控调度（含科目路由）
4. 学习模式会话预设 + npm 安装入口
5. 示例课程端到端验证

验收标准：
- [ ] 开场能读共享记忆、列出科目；新课先盘问再建课
- [ ] 能生成大纲路线图，逐知识点学习
- [ ] 每个知识点产出一份 HTML 课件（含交互练习），能打开给学生
- [ ] 讲解体现人话原则；说"没听懂"会换讲法
- [ ] 四层练习可出题、可评估，评价到"能独立完成项目"
- [ ] 局部提问不污染主对话，记录只进当前科目
- [ ] 两个科目互不干扰，共享记忆可读写
- [ ] 会话结束生成摘要，新会话能恢复进度
- [ ] 换机器重新安装并指定原学习工作区后能续学

### 阶段二：主页体系（升级体验）

6. 根主页 + 科目主页生成（模板在 `templates/`，生成器是 `scripts/gen_home.py`）
7. 主页与学习流程打通（点击节点开课件、状态变化后自动刷新）

验收标准：
- [ ] 根主页列出所有科目，可进入科目主页
- [ ] 科目主页渲染大纲路线图（按状态着色），点击节点打开课件
- [ ] 点大纲节点展开课件子卡片，点课件能打开；附件区列出速查文档/术语表/学习记录
- [ ] 状态或课件变化后，主页自动反映新状态

## 10. 风险与边界

| 风险 | 应对 |
|------|------|
| 内容准确性（尤其易变 API/版本细节） | 按分级核对：易变内容与冷门领域必须查官方文档；课件标注来源类型，不为凑引用而引用 |
| 实操跑不起来（环境/依赖差异） | 首课即确定本技术栈的环境与验证方式并记进 `lab/README.md`；引导部分先给结果兜底，学生看到再动手 |
| 学生伪装"学会了" | 以代码运行结果 + 测试 + 解释为证据，不只凭口头确认 |
| 单会话仍超长 | 按知识点切分会话；每节点结束写盘，下次从摘要恢复 |
| 共享记忆长期膨胀或写歪 | 只增补与修正，不整篇重写；定期人工清理过时条目 |
| 弱约束下讲解风格飘忽 | 用共享记忆记录"什么讲法有效"，逐步收敛到最适合这个学生 |
| 多科目文件串味 | 科目互不引用，只有共享记忆是公共通道 |
| 盘问太长让人烦 | 每轮只问现在就能答的问题，一次问完；问过的不再问 |
| 主页显示旧状态 | 主页是生成产物，状态变化后自动重新生成，不手改 |
