# Mission: 线性代数

## Why

机器学习的教材和论文里到处是矩阵符号，现在只能整段跳过：字母都认得，符号之间的关系读不出来，也就
判断不了这一步到底在做什么。这门课要把那些符号换成能看见的东西——几支箭头怎么拼出目标箭头、一个
矩阵把平面压成了什么、一个方程组到底有几个解。学成之后拿到一段公式，能先说出它在做什么，再决定
要不要动手算。

## Success looks like

- 拿到一个线性方程组，能说清它是唯一解、无解还是有自由变量，并手写消元把解写出来
- 看到 $Ax = b$ 能说出「用 $A$ 的列向量去拼 $b$」，看到 $A$ 能说出它把哪些方向压扁、哪些方向没动
- 能用 Python 标准库写出一个方程组求解器（化简 + 判断解的结构），并用手算结果核对它的输出
- 读完一份讲特征分解的应用材料（人口迁移或图像压缩），能说出这一步在真实过程里对应什么

## Constraints

- 数学底子：微积分学过、能用；线性代数零基础，只会解二元一次方程组
- 编程底子：Python 能写小脚本（读写文件、循环、装包）；C 语言上过一学期，指针生疏
- 时间：每周 3~4 次、每次 40 分钟，一个知识点一节课
- 偏好：先看「这解决什么问题」→ 用具体数字走一遍 → 最后才给定义和符号；公式堆在前面会卡住
- 卡点预警：抽象符号（矩阵、下标）容易卡，需要先把过程具体化再抽象

## Out of scope

- 数值线性代数（稀疏矩阵、迭代解法、条件数与稳定性）——先把几何直觉与手算练熟
- 抽象代数与泛函分析（向量空间公理化、线性泛函、无穷维空间）
- 矩阵微积分与张量运算（自动求导、反向传播的推导）——留到需要时再补
- 用 numpy 这类第三方库代劳本课的求解器——lab 只用标准库，写完之后再对照现成库
